1. RISC-V passes the first eight integer or pointer arguments in a0 through
a7.  In main's call to printf, the value 13 is the third argument and is held
in a2.  The format string is in a0 and f(8)+1 (which is 12) is in a1.

2. There is no call instruction for either f or g in main.  The compiler
inlined both functions and constant-folded the result, so main simply loads 12
into a1 before calling printf.

3. In the call.asm generated by the completed traps branch, printf starts at
address 0x64e.

4. The jalr that calls printf is at address 0x3c.  Immediately after it takes
effect, ra contains 0x40, the address of the next instruction in main.

5. The program prints "He110 World".  57616 is 0xe110, and little-endian
memory stores i as bytes 72 6c 64 00, which form the string "rld".  On a
big-endian machine i should be 0x726c6400 to place those bytes in the same
address order.  The integer 57616 does not need to change, because %x formats
its numeric value rather than interpreting its byte sequence as a string.

6. The text after "y=" is indeterminate (and the C call has undefined
behavior), because the format requests a second integer but printf was given
only one.  printf will read whatever unrelated value happens to be in the
register/argument position where the missing value should have been.
